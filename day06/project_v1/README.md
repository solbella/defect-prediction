# 설비 고장 예측 (project_v1)

**한 문장**: 설비의 운전 조건(온도·회전수·토크·공구마모)으로, 실제 고장이 나기 전에 고장 가능성이 높은 상태를 미리 골라낸다.

## 한눈에 보기

- 오늘 정한 문제: 설비 측정값으로 정밀 재검사(점검) 대상을 먼저 고르는 것
- 쓴 데이터: 설비 운전 기록 10000행 × 7열 / 고장 339건(3.39%)
- 오늘 나온 숫자: 기준 모델 96.6% / 내 모델 v1 96.85% / 지목 13건 중 진짜 9건 / 재현율 0.132
- 다음에 손댈 자리: 지목 건수를 늘리는 설정

## 문제 정의

| 물음 | 답 |
|---|---|
| 누가 쓰나 | 설비 유지보수(정비) 담당자 |
| 무엇을 결정하나 | 이 설비를 지금 멈춰서 점검·정비할지, 그대로 가동할지 |
| 언제 결정하나 | 센서값(온도·회전수·토크·공구마모)이 들어오는 가동 중, 실제 고장이 나기 전 |
| 이 판단이 늦으면 | 가동 중 갑자기 멈추는 다운타임으로 생산이 끊기고, 부품·공구 손상과 수리 비용·정지 시간이 함께 늘어날 수 있다 |

## 한계

| 한계 | 실행으로 확인한 근거 |
|---|---|
| 고장 건수가 절대적으로 적다 | 전체 고장 339건(3.39%). 시험용 20%로 나누면 약 68건만 남아, 재현율·정밀도가 나눌 때마다 크게 흔들릴 수 있다 |
| 조건 열끼리 정보가 겹친다(다중공선성) | `Air temperature`↔`Process temperature` 상관계수 0.876, `Rotational speed`↔`Torque` 상관계수 -0.875 — 조건 열 5개지만 실질 독립 정보량은 그보다 적다 |
| 지나치게 깨끗한(시뮬레이션형) 데이터 | 결측치 0건, 중복 행 0건 — SECOM(결측치 다수)·콜드체인(155건 결측) 같은 실제형 데이터와 달리 노이즈가 없어, 여기서 잘 나온 성능이 실제 현장 데이터에서도 그대로 나올지는 별개 문제다 |

## 결과

| | 정확도(전체 중 맞힌 비율) | 지목 | 그중 진짜 | 정밀도(지목한 것 중 진짜였던 비율) | 재현율(실제 있던 것 중 잡아낸 비율) |
|---|---|---|---|---|---|
| 기준 모델 (전부 정상) | 96.6% | 0건 | 0건 | 0.000 | 0.000 |
| 내 모델 v1 | 96.85% | 13건 | 9건 | 0.692 | 0.132 |

시험용에 실제로 있던 고장: **68건**. 정확도(전체 중 맞힌 비율)는 기준보다 **0.25**%p 올랐고, 지목한 13건 중 9건이 실제 고장이었다(정밀도 0.692). 다만 실제 68건 중 **59**건은 못 잡았다(재현율 0.132 = 9건 ÷ 68건). 그래서 정확도만으로는 판단할 수 없는 문제였다.

### 추가로 해본 것 — class_weight="balanced"

| 모델 | 지목 건수 | 그중 진짜 | 재현율 |
|---|---|---|---|
| 손 안 댐 | 13 | 9 | 0.132 |
| 가중치 | 404 | 57 | 0.838 |

가중치를 주니 재현율이 0.132→0.838로 오르지만, 지목 건수도 13건→404건으로 늘었다(그만큼 헛경보도 늘었다는 뜻).
