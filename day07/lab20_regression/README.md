**한 줄 요약**: 공정 조건 다섯 가지로 고장 여부를 판별한다.

| 실습 | 내용 |
|---|---|
| 실습 20 | 회귀 연습 — 같은 데이터로 공정온도(Process temperature)를 숫자로 맞혀보기 |
| (직접 해보기) | 맞히는 대상을 토크(Torque)로 바꿔 같은 방식으로 다시 돌려보기 |

## 덤 — 회귀 연습에서 알아낸 것 (비전문가용)

카드 여덟 칸은 "고장을 맞히는" 분류 문제만 다룬다. 그런데 이 노트북 앞부분(실습 20과 직접 해보기)에서는 같은 데이터로 "숫자를 맞히는" 연습도 했다. 정상/고장을 맞히는 대신, 온도나 힘 같은 숫자 자체를 예측해본 것이다.

- **공정온도를 맞혀보니**: 다른 값들(공기온도·회전속도·토크·공구마모)을 함께 보고 공정온도를 꽤 잘 맞혔다(설명력 약 76%). 그런데 자세히 들여다보니, 모델은 사실상 "공기온도" 하나만 보고 맞히고 있었다 — 공기온도가 오르면 공정온도도 거의 그대로 따라 오르는, 두 온도가 서로 강하게 붙어 움직이는 값이었기 때문이다. 나머지 세 값(회전속도·토크·공구마모)은 거의 참고하지 않았다.
- **토크를 맞혀보니**: 맞히는 대상을 토크로 바꿔도 비슷한 수준으로 잘 맞았다(설명력 약 76%로 공정온도 때와 거의 같음). 즉 이 데이터는 무엇을 대상으로 바꾸든 비슷한 방식(선형회귀)으로 어느 정도 예측이 가능했다.

이 부분은 "고장을 미리 알아채는" 본 프로젝트의 결과가 아니라, 같은 데이터로 회귀라는 다른 방법을 연습해 본 준비 운동에 가깝다.

---

아래 내용은 실습 23의 "카드 여덟 칸"을 그대로 옮긴 것이다.

## 1. 왜 이 문제인가

고장을 놓치면 라인이 멈춘다. 멈춘 뒤에 아는 것과 미리 아는 것은 비용이 다르다.

## 2. 사용 데이터

이 저장소에는 데이터 파일이 포함되어 있지 않습니다. 사용한 파일은 `data/16_machine-failure.csv`이며, 원본은 [AI4I 2020 Predictive Maintenance Dataset](https://archive.ics.uci.edu/dataset/601/ai4i+2020+predictive+maintenance+dataset) (UCI)로 최상단 [`README.md`](../../README.md)에 기록되어 있습니다.

- 공개 데이터 / 10,000행 x 7열
- 결과 열은 정상·고장
- 고장 339건 (3.39%)

## 3. 무엇을 했나

숫자 열 5개(공기온도·공정온도·회전속도·토크·공구마모)를 입력으로 씀 / 결측치가 0건이라 따로 채울 것은 없었음 / 학습용과 시험용을 8대 2로, 고장 비율을 맞춰 나눔(stratify) / 표준화(StandardScaler) 후 로지스틱 회귀로 학습, 전부 정상이라 답하는 기준 모델과 견줌

## 4. 결과 수치

전부 정상이라 답하는 기준 모델 96.60% 대비 96.85%. 지목한 13건 중 9건이 진짜 고장이었으나, 실제 68건 중 59건은 놓쳤다. 정확도만 보면 차이가 없어 보여 재현율을 함께 봤다.

## 6. 의사결정 가치

놓친 고장이 헛경보보다 비싼 현장이라면 문턱을 낮춰 지목을 늘리는 편이 낫다.

## 7. 한계와 다음

한 기간의 공개 데이터라 다른 라인에 그대로 적용된다고 보기 어렵다. 어느 항목이 원인이라고 말할 수는 없다.

- 고장 건수가 절대적으로 적다
